# v0.0.11

## New

- **Required Actions** (`woodglue.access`, `woodglue.apps.rpc`): a method can
  declare `requires="<action>"` (lythonic `@nsnode`, `Namespace.register`, or
  `requires:` on a YAML entry), naming an action of its namespace such as
  `write`. Only a Grant for that action on the namespace runs it, so `call`,
  `call ns*`, and `call *` no longer reach it, and `write ns` alone runs only
  those methods. The built-in `admin` Role reaches every action. See
  [Access control](../how-to/access-control.md) and ADR 0005.
- Firing or activating a trigger needs its method's Required Action as well as
  `trigger`.
- `system.list_methods` and `system.describe_method` report `required_action`
  and `can_call`. `llms.txt`, method doc pages, and `openapi.json`
  (`x-required-action`) show the Required Action, and the Console marks such
  methods and greys out those the viewer cannot run.
- Startup warnings for Grants that reach nothing: a Role or UI Grant naming an
  action no loaded namespace declares, and a namespace Grant whose pattern has
  a dot (such as a leftover `call cointoss.portfolio`).

## Changed

- **Breaking:** `Grant.parse` accepts any lowercase action name as a
  namespace-declared action, so an unknown action in `auth.roles` or a UI's
  `grants` is no longer a config error; it is the startup warning instead.
  Invalid names still fail, now with `Invalid action ...`.
- **Breaking:** a node declaring `read`, `trigger`, `view`, or `admin` as its
  Required Action fails at startup.
- `Grant.action` is `Action | str`; `check` and `Caller.can` take plain-string
  actions.
- Static UIs: with tornado 6.6, files reached through a symlink that points
  outside the UI's directory answer 403.

## Documentation

- ADR 0005: namespace-defined Required Actions.
- Glossary adds "Action" and "Required Action".
- `mkdocs build --strict` passes again.

## Dependencies
