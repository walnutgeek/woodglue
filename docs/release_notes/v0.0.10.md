# v0.0.10

## New

- **Pending Users and approval** (`woodglue.auth_store`, `woodglue.access`): a User
  has a status of `pending`, `active`, or `disabled`. An Identity Provider's
  `admit_as: pending` admits new Users without Grants until an admin approves them
  with `wgl user approve` or `system.approve_user`. A pending User listed in
  `auth.admins` becomes active at sign-in. Pending Users cannot create tokens.
- **Delete a User**: `AuthStore.delete_user`, `wgl user delete`, and
  `system.delete_user` remove a User with their Role assignments, provider links,
  Sessions, and tokens.
- **Console Users page** for admins: list Users, approve, disable, re-enable,
  delete, and assign or unassign Roles. The built-in admin cannot be disabled,
  deleted, or lose `admin`.
- **No-access page**: a signed-in User without Grants who opens a UI sees an
  "awaiting approval" page (pending) or a "no access" page (active) instead of a
  bare 403, through Caddy's `forward_auth` too.
- **`package:` references** in `uis`: `app` and Static UI `path` accept
  `package:<import name>/<path>`, resolved inside the installed package without
  importing it. `wgl caddy config` proxies such Static UIs to woodglue.

## Changed

- **Breaking:** `auth.db` migrates in place to schema version 2; older woodglue
  versions cannot open it afterwards.
- **Breaking:** `system.list_users` returns `User.status` instead of
  `User.disabled`.
- **Breaking:** `system.describe_initiators` requires `read` on some namespace.
- `system.list_roles` is admin-only; `RoleInfo` gains `builtin` and `WhoAmI`
  gains `admin`.
- `AuthStore.unassign_role` refuses to remove `admin` from the built-in admin.
- `wgl user`, `wgl token`, `wgl run`, and `wgl caddy config` load
  `woodglue.yaml` without expanding provider secrets, so they work where those
  environment variables are unset.

## Fixes

- `/`, `/ui`, and `/ui/` redirect to the default UI with a 302 instead of a 301,
  so browsers no longer keep the old `/ui/` target from v0.0.8.
- Secrets in query strings (OAuth `code`, `state`, `token`) are redacted from
  request and error logs (`woodglue.apps.server`).

## Documentation

- How-tos for access control, identity providers, static UIs, Streamlit UIs, and
  Caddy cover pending Users, approval, `package:` references, and the no-access
  page.
- Glossary adds "User status" and "Role assignment".

## Dependencies

- `pydantic-yaml` moves to dev dependencies
